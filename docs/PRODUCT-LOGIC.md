# Derayes: claim boundaries and participation model

## Defensible product claim

Derayes organises asset-backed project evidence, review status, disclosed risks, and ongoing updates to support informed assessment.

This proof of concept demonstrates that workflow. It does not establish the truth of any asset claim, endorse an investment, or admit anyone to a project.

## What is implemented

- Three fictional project profiles, with sector filtering and readable sample evidence.
- Arithmetic for planned allocations, reported spending, balances, and percentages, in Nigerian naira.
- Fixed illustrative review outcomes: five reviewed items and one open item. These outcomes are fixture data, not decisions generated by a verification engine.
- A fictional reporting timeline.
- A real SHA-256 calculation of a fixed JSON snapshot, compared with a stored demo hash.
- Accessible navigation, document dialogs, expandable risk/checklist rows, and a browser copy action.

There is no user account, application, registration, investment, payment, persistence, independent reviewer integration, legal-title lookup, credit evaluation, or bank reconciliation. The static frontend makes no submission to a project operator.

## What the hash establishes

A matching hash establishes only that the displayed snapshot matches the reference shipped with this demo. It does not establish authorship, factual accuracy, asset ownership, value, or a trusted timestamp. A party able to change both the snapshot and its reference hash can produce a matching result. The mock record history is not an immutable or independently witnessed registry.

## Recommended pilot: expression of interest

This is a proposed future workflow, not a feature implemented in the current demo:

1. A visitor reads the evidence and unresolved risks.
2. The visitor selects “Express interest” or “Request more information”.
3. A form explains that this is a non-binding enquiry with no allocation, ownership, contract, payment, or promised return. It records contact and sharing consent under an appropriate privacy notice.
4. An authenticated backend records a unique enquiry reference, timestamp, project version, and consent; prevents duplicate/spam submissions; and restricts access to authorised staff.
5. An authorised operator reviews the enquiry and follows up only within the visitor's consent.

An interest record can demonstrate demand and consent to contact. It must not be presented as acceptance into a project or evidence that the project is legitimate. Wording and actual conduct both matter; a label alone is not a legal exemption.

## Before real participation

The intended relationship must be defined first: buyer, tenant, supplier, cooperative member, lender, shareholder, or another category. Each has different rights and obligations. The project needs an identified legal counterparty, independently supported asset/ownership claims, the required permissions, a documented review process, accurate disclosures, and agreements stating what participants receive and what happens if the project fails.

Where the service involves investment-based crowdfunding in Nigeria, assess the applicable SEC framework with qualified Nigerian counsel and appropriately registered operators before solicitation or onboarding. Avoid assuming that not directly holding funds removes regulatory obligations. Any authorised financial flow should be separately designed, including identity checks, applicable AML controls, custody/payment arrangements, complaints, and dispute handling.

Future review records should identify the document version, submitter, qualified reviewer, source of confirmation, scope, date, findings, unresolved items, and expiry/re-review conditions. “Document received”, “consistency checked”, and “independently confirmed” are different statuses and should never be collapsed into an unexplained “verified” badge.

## Hosting

GitHub Pages fits this static, non-transactional project demo. It does not provide an application backend. GitHub's usage limits exclude running transaction-focused businesses or commercial SaaS on Pages, so a live participation service requires an appropriate hosting architecture and assessment of provider terms.
